# darkforge 0.2.0: fewer main-session turns

Date: 2026-11-26 · Status: draft for owner approval

## 1. Why

The first live end-to-end run (checklist run A, 2026-11-25, `docs/testing/e2e-checklist.md`) measured where tokens go:

- The main session (orchestrator) used **85%** of all tokens (4.43 M of 5.24 M); subagents 15%. 93% of all tokens were cache reads.
- `next-task` for task 001 ran in a **fresh** session and still cost the orchestrator 1.02 M tokens, against 285 k (implement) + 40 k (review).
- Its transcript: **21 main-session model calls**, context growing from 37 k to 53 k tokens. Every call re-reads the whole context, so the cost is roughly calls × context.
- About 12 of the 21 calls were mechanical: `task start`, loading the `model-routing` skill and grepping `riskAreas` (the package header already names agent and models), three `ledger phase` calls, two `ledger report` calls, `git add` / `git commit` of the memory bank, `memory lint`, `gate`, `task merge`.

The 0.1.0 design already says: "Mechanical steps are deterministic Node.js scripts bundled in the plugin; the model only makes judgment calls." 0.2.0 makes `next-task` (and the closing steps of `plan-phase` and `phase-review`) follow it.

## 2. Goal and non-goals

Goal: cut the main-session model calls per task roughly in half without changing what is checked or who decides.

Target, to be measured by re-running checklist run A on the same fixture: orchestrator tokens per `next-task` at least 40% lower than run A (task 001: 1.02 M; task 002: 0.60 M). This is a target, not a promise; the result is recorded either way.

Non-goals: an unattended runner, the dashboard, changes to subagents, routing or the review process, new config fields beyond those below.

## 3. Changes

### 3.1 `darkforge task begin <id>`

One command replaces steps "read package header", `task start`, routing lookup and `ledger phase implement`.

- Reads `docs/tasks/<id>-*.md`, parses the header line (`Agent · Model · Branch · Reviewer · Risk`). Refuses if the file is missing, the header is malformed, or the slug in `Branch` does not match the file name.
- Refuses if `## Waiting on owner` lists a `Q-NN` whose row names this task in its "Blocks" column (same rule the skill applies now, made deterministic).
- Checks the header's models against the config: banned, floors, `models.tiers` (the guard would deny them later anyway; failing here is earlier and clearer).
- Runs the existing `task start` logic, then sets the ledger phase to `implement`.
- Prints one short block the skill reads:
  ```
  task 001 started on task/001-validated-multiply (risk medium)
  implementer: darkforge:builder model sonnet
  reviewer: darkforge:reviewer model opus
  base: main
  ```
- Resuming (state already names this task and the branch exists): does not start again, prints the same block plus `resumed`.

The `model-routing` skill is loaded only for escalation after failed fix rounds.

### 3.2 `darkforge task finish <id> --title "<title>"`

One command replaces `ledger report` (for the token number), `git add memory-bank/`, the memory-bank commit, `memory lint`, `gate`, `ledger phase orchestrator`, `task merge` and the final `ledger report`.

In order, stopping at the first failure with that step's output:

1. Fills the task's token total into its `progress.md` row: the skill writes the row with `-` in the Tokens column; `finish` replaces it with the ledger total so far (implement + review + fix + orchestrator recorded until now).
2. `git add memory-bank/` and commits `docs: task <id> memory bank` (only if memory-bank has changes).
3. `memory lint`.
4. `gate` (quiet). On failure, prints the failing lines and `next: fix round` so the skill sends them to the implementer.
5. `ledger phase orchestrator`, then the existing merge logic (same refusals, same PR / local / merge-queue behaviour).
6. Prints the task's ledger row and the merge result.

Re-running after a fixed gate failure continues from step 2.

### 3.3 Ledger phase on dispatch

The model-guard hook already sees every `Agent` call. When it allows a call to a darkforge agent in a darkforge project with an active task, it also sets the ledger phase: implementer agents (`builder`, `specialist`, `scaffolder`) → `implement`; reviewer agents (`reviewer`, `security-reviewer`) → `review`. Fix rounds go through `SendMessage`; the skill still runs `darkforge ledger phase fix` and `... review` around them (one call each, only when a fix round happens).

### 3.4 Skill changes

- `next-task`: steps become pick (read the two memory-bank files) → `task begin` → dispatch implementer → dispatch reviewer → fix rounds if any → edit memory bank → `task finish` → report. The report's last line tells the owner to start a fresh session (`/clear`) before the next task.
- `plan-phase` and `phase-review`: their closing steps use `task finish` (it works for `P<N>` and `P<N>R` ids).
- Skills get shorter; the size test budget stays at 4600 bytes.

### 3.5 Docs

- User guide: what `begin` and `finish` do; "one task per session"; the measured token split from run A and that the main session's model is the session model, so running the main session on a cheaper model lowers cost (the subagents keep their routed models).
- Config reference: no new fields.

## 4. Risks

- A CLI that does more can hide a step from the owner. Mitigation: each step prints one line; any failure prints that step's own output, as now.
- Parsing the package header becomes a contract. Mitigation: `task-package-writing` already fixes its format; `begin` names the exact problem when it does not parse; tests cover the template.
- Filling the token number before the merge records slightly fewer orchestrator tokens than the final total (the last turn lands at the next Stop). Same as today; documented.
- Phase on dispatch in a hook: a hook error must never block an allowed call. Mitigation: the phase write is best effort and the hook fails open, like the ledger.

## 5. Verification

- Unit tests for `begin` and `finish` (all refusal paths, resume, gate failure then re-run), the hook phase write, and the header parser against the template.
- `test/e2e-cli.test.mjs` switches to `begin` / `finish`.
- Re-run checklist run A on the same fixture; record per-task orchestrator tokens next to run A's. Independent review before merge.
